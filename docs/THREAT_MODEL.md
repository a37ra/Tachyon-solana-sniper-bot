# Модель Угроз и Защита (Threat Model)

Этот документ описывает ключевые векторы атак (ТЗ 3.1-3.6) и реализованные механизмы защиты.

## 1. Компрометация ключа через память процесса

**Угроза:** Злоумышленник (или RCE уязвимость в логике стратегии) читает память процесса для извлечения приватного ключа Hot Wallet.
**Mitigation:** 
- Физическое разделение на два процесса: `solbot-strategy` (сложная логика, нет ключа) и `solbot-signer` (минимальная логика, держит ключ).
- Использование `mlock` в `solbot-signer` для запрета сброса страниц памяти в swap.
- Systemd hardening (`LimitCORE=0`, `MemoryDenyWriteExecute=true`, `ProtectSystem=strict`).

## 2. Replay Attack (обход ipc_seq)

**Угроза:** Злоумышленник перехватывает валидный IPC запрос к signer и отправляет его повторно, чтобы заставить signer подписать дублирующую транзакцию.
**Mitigation:**
- Монотонный счетчик `ipc_seq` на каждый `context_key`.
- Signer сохраняет `last_ipc_seq` в SQLite (`ipc_sequence_ledger`) атомарно с логом аудита (`signer_audit_log`).
- После рестарта signer сначала загружает ledger, не допуская обнуления счетчика.
- Любой запрос с `ipc_seq <= last_ipc_seq` немедленно отклоняется.

## 3. Stale Intent Injection

**Угроза:** Задержки в сети или IPC приводят к тому, что старый intent доходит до signer слишком поздно (когда рыночная ситуация уже изменилась).
**Mitigation:**
- Поле `issued_at_unix_ms` в `SignerIntentRequest`.
- Signer проверяет возраст intent: `now_ms - issued_at_unix_ms <= 500`. 
- Все старые intent отклоняются.

## 4. Unexpected Destination Drain

**Угроза:** Злоумышленник подменяет инструкцию в неподписанной транзакции, направляя средства на свой кошелек вместо пула DEX.
**Mitigation:**
- Signer проверяет `program_id` по жесткому allowlist (Raydium, Meteora, Pump.fun).
- Signer проверяет адреса назначения. Транзакции на неизвестные адреса отклоняются, вызывая emergency drain в Cold Reserve (если настроено) и активируя kill switch.

## 5. Signing Rate Anomaly (Утечка средств мелкими транзакциями)

**Угроза:** Злоумышленник обходит лимиты `max_size_absolute`, отправляя огромное количество мелких запросов на подпись.
**Mitigation:**
- Signer ведет учет количества запросов за 5 минут.
- Порог аномалии (`signing_rate_threshold_5min`) рассчитывается как `ceil(max_concurrent_positions * 13.5)`. 
- Превышение порога вызывает отказ в подписи, отправляет алерт и приостанавливает новые входы.

## 6. MEV (Front-running / Sandwich attacks)

**Угроза:** Потеря средств из-за манипуляций приоритетом транзакций в публичном мемпуле.
**Mitigation:**
- Primary Route: Использование Jito Bundles для отправки транзакций напрямую в приватный мемпул валидатора.
- Fallback Route (при деградации Jito): Рандомизированный micro-jitter комиссии/типа для усложнения паттерн-матчинга ботами-паразитами. Эскалация комиссии происходит *между* стадиями (Stage 1 -> Stage 2), а не на каждый ретрай.
