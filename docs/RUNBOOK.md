# Solana Sniper Bot - Runbook

Этот документ описывает типовые процедуры оператора для управления ботом и реагирования на аварийные ситуации.

## 1. Процедура при Stage 3 (Stuck Manual Intervention Required)

Эта ситуация возникает, когда бот не смог выйти из позиции даже после применения максимального slippage на публичных RPC-нодах, и транзакция перешла в состояние "durable nonce retry".

**Действия:**
1. Проверьте статус позиции и текущую цену. Бот будет пытаться переотправить подписанную транзакцию каждые 5 секунд.
2. Проверьте сеть (RPC / Jito) — возможно, сеть перегружена.
3. Если текущая цена вас устраивает, и бот не может закрыть позицию по техническим причинам, используйте принудительное закрытие через CLI (см. ниже).
4. Если сеть недоступна, вы можете закрыть позицию вручную через Phantom/Solflare, переведя токены на другой кошелек и продав там, но после этого бот не будет знать о продаже. Необходимо вручную обновить статус позиции в базе данных на `closed`.

## 2. Процедура force-close через CLI

Если позиция зависла, можно принудительно завершить ее через CLI.

```bash
solbot-cli position force-close <position_id>
```

Это действие:
1. Попытается отправить новую транзакцию с максимальным приоритетом и проскальзыванием.
2. Если не удастся, переведет позицию в статус `closed` (или `stuck`) и отменит фоновые ретраи. 

## 3. Процедура Circuit Breaker Reset

Circuit breaker останавливает новые входы при достижении дневного лимита убытка. Сброс происходит автоматически в 00:00 UTC. Если необходимо сбросить его вручную (например, после изменения настроек или исправления ошибки):

```bash
solbot-cli circuit-breaker reset
```
Осторожно: это действие немедленно разрешит боту открывать новые позиции.

## 4. Процедура ротации ключей (3.5)

Секреты (Jito Auth, Telegram Bot Token, RPC keys) хранятся в Vault или файле `.env` / защищенном хранилище.

**Ротация Telegram/RPC ключей:**
Обновите ключи в Vault/файле и отправьте команду перезапуска соответствующему сервису:
```bash
sudo systemctl restart solbot-telegram
sudo systemctl restart solbot-strategy
```

**Ротация приватного ключа Hot Wallet:**
1. Выключите бота: `sudo systemctl stop solbot-strategy solbot-signer`
2. Сгенерируйте новый ключ. Создайте новый Durable Nonce Account для нового кошелька (скрипт `create_durable_nonce_account.sh`).
3. Зашифруйте новый ключ и поместите в Vault/хранилище.
4. Обновите конфиги (балансы, rent-exempt минимумы).
5. Запустите: `sudo systemctl start solbot-signer solbot-strategy`

## 5. Процедура восстановления из бэкапа Litestream

Litestream постоянно реплицирует WAL SQLite. В случае падения базы или порчи файла:

1. Остановите сервисы: `sudo systemctl stop solbot-strategy solbot-signer`
2. Переместите поврежденный файл БД: `mv ./solbot.db ./solbot.db.bak`
3. Восстановите базу из S3/GCS:
```bash
litestream restore -config ./deploy/litestream/litestream.yml -o ./solbot.db s3://<ваша-корзина>/solbot.db
```
4. Запустите сервисы: `sudo systemctl start solbot-signer solbot-strategy`
